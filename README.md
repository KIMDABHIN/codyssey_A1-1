# AI 프롬프트 관리 프로그램

## 1. 프로젝트 개요

Python을 활용하여 콘솔 기반의 AI 프롬프트 관리 프로그램을 제작하였다.

프롬프트를 추가하고 목록으로 확인할 수 있으며, 카테고리별 조회, 키워드 검색, 상세 보기, 즐겨찾기 관리, 수정 및 삭제 기능을 구현하였다.

또한 Git과 GitHub를 활용하여 기능별로 변경사항을 커밋하고, 별도의 feature 브랜치에서 기능을 개발한 후 main 브랜치에 병합하는 과정을 수행하였다.

# 2. 개발 환경

- 운영체제: Windows
- 개발 도구: Visual Studio Code
- 프로그래밍 언어: Python
- Python 버전: 3.10 이상
- 버전 관리 도구: Git
- 원격 저장소: GitHub
- 기본 브랜치: main

### 개발 환경 확인 방법

Python 버전은 다음 명령어로 확인할 수 있다.

python --version

Git 버전은 다음 명령어로 확인할 수 있다.

git --version

Git 사용자 이름은 다음 명령어로 확인할 수 있다.

git config --global user.name

Git 사용자 이메일은 다음 명령어로 확인할 수 있다.

git config --global user.email

GitHub 계정과 로컬 Git 저장소를 연결하여 프로젝트를 원격 저장소에 업로드하였다.

# 3. Git 저장소 설정

Git 저장소는 다음과 같은 과정으로 구성하였다.

1. GitHub에 프로젝트 저장소를 생성하였다.
2. 로컬 프로젝트 폴더에서 Git 저장소를 초기화하였다.
3. GitHub 원격 저장소를 연결하였다.
4. 파일을 staging 영역에 추가하였다.
5. commit을 생성하였다.
6. GitHub 원격 저장소에 push하였다.
7. feature 브랜치를 생성하여 기능을 별도로 개발하였다.
8. 작업이 완료된 후 main 브랜치에 merge하였다.

### 주요 Git 명령어

git init
git add .
git commit -m "커밋 메시지"
git push
git pull
git checkout -b feature/브랜치명
git checkout main
git merge 브랜치명

또한 공개 샘플 저장소를 git clone 명령으로 내려받아 저장소의 폴더 구조와 Git 로그를 확인하는 과정을 수행하였다.

git clone 저장소주소

clone은 원격 저장소의 프로젝트와 Git 이력을 로컬 컴퓨터로 복사하여 확인하거나 작업할 수 있도록 하는 명령이다.

Python 3.10 이상이 설치된 환경에서 실행할 수 있다.

터미널에서 프로젝트 폴더로 이동한 후 다음 명령어를 실행한다.

프로그램이 실행되면 메뉴 번호를 입력하여 원하는 기능을 선택할 수 있다.

# 5. 주요 기능

## 1. 프롬프트 추가

제목, 내용, 카테고리를 입력하여 새로운 프롬프트를 등록한다.

- 제목 입력
- 내용 입력
- 카테고리 선택
- 빈 값 입력 시 다시 입력
- 동일한 제목의 프롬프트 중복 등록 방지
- 즐겨찾기 기본값은 False

입력 과정에서 q를 입력하면 현재 작업을 취소하고 메인 메뉴로 돌아갈 수 있다.


## 2. 프롬프트 목록 보기

등록된 모든 프롬프트를 번호와 함께 확인할 수 있다.

목록에는 다음 정보가 표시된다.

- 프롬프트 번호
- 제목
- 카테고리
- 즐겨찾기 여부(⭐)


## 3. 프롬프트 삭제

원하는 프롬프트를 선택하여 삭제할 수 있다.

삭제 전 확인 과정을 거치며, 잘못된 번호를 입력하면 안내 메시지를 표시한다.


## 4. 프롬프트 수정

기존 프롬프트의 정보를 수정할 수 있다.

현재 수정 기능에서는 다음 항목을 수정할 수 있다.

- 제목
- 내용

제목을 변경할 경우 기존 프롬프트와 동일한 제목이 존재하는지 확인하여 중복 등록을 방지한다.

카테고리 변경이 필요한 경우 수정 함수에서 해당 프롬프트의 category 값을 입력받도록 확장할 수 있다.


## 5. 카테고리별 조회

원하는 카테고리를 선택하여 해당 카테고리에 속한 프롬프트만 확인할 수 있다.

현재 사용 가능한 카테고리는 다음과 같다.

- 텍스트 생성
- 이미지 생성
- 영상 생성
- 페르소나
- 자동화
- 기타

선택한 카테고리에 해당하는 프롬프트가 없으면 안내 메시지를 출력한다.


## 6. 프롬프트 검색

키워드를 입력하여 프롬프트를 검색할 수 있다.

검색 대상은 다음과 같다.

- 제목
- 내용
- 카테고리

검색은 대소문자를 구분하지 않도록 처리하였다.

예를 들어 블로그를 검색하면 제목이나 내용에 블로그가 포함된 프롬프트를 찾아 출력한다.

검색 결과가 없으면 안내 메시지를 출력한다.


## 7. 프롬프트 상세 보기

프롬프트 번호를 입력하면 해당 프롬프트의 상세 정보를 확인할 수 있다.

다음 정보를 표시한다.

- 제목
- 카테고리
- 즐겨찾기 여부
- 프롬프트 전체 내용

잘못된 번호를 입력하면 안내 메시지를 출력한다.


## 8. 즐겨찾기 추가/해제

프롬프트 번호를 입력하여 즐겨찾기를 추가하거나 해제할 수 있다.

즐겨찾기 상태는 Boolean 값인 True 또는 False로 관리한다.


## 9. 즐겨찾기 목록 보기

즐겨찾기로 설정된 프롬프트만 모아서 확인할 수 있다.

즐겨찾기 상태인 프롬프트는 목록에서 ⭐ 표시로 구분한다.


## 10. 작업 취소

입력 과정에서 q를 입력하면 현재 작업을 취소하고 메인 메뉴로 돌아갈 수 있다.

이를 통해 잘못된 기능을 선택했거나 입력을 중단하고 싶은 경우 프로그램을 종료하지 않고 다시 메뉴를 사용할 수 있다.

# 6. 프로그램 입력 검증

사용자의 잘못된 입력으로 프로그램이 중단되지 않도록 기본적인 입력 검증을 적용하였다.

### 빈 값 검증

제목이나 내용 등 필수 입력 항목이 비어 있으면 다시 입력하도록 처리한다.

### 메뉴 번호 검증

메뉴에서 존재하지 않는 번호를 입력하면 잘못된 메뉴 번호라는 안내를 출력하고 다시 메뉴를 표시한다.

### 번호 범위 검증

프롬프트를 선택하는 기능에서는 존재하지 않는 번호를 입력할 경우 안내 메시지를 출력한다.

### 중복 제목 검증

새로운 프롬프트를 추가할 때 기존 프롬프트와 동일한 제목이 존재하면 등록하지 않는다.

프롬프트 수정 시에도 변경하려는 제목이 다른 프롬프트와 중복되는지 확인한다.

### 작업 취소

입력 과정에서 q를 입력하면 현재 작업을 취소하고 메인 메뉴로 돌아간다.

# 7. 코드 구조와 함수 분리

프로그램의 모든 기능을 하나의 함수에 작성하지 않고 기능별로 함수를 분리하였다.

주요 함수는 다음과 같은 역할을 담당한다.

- show_menu() : 프로그램의 메인 메뉴를 출력한다.
- add_prompt() : 새로운 프롬프트를 입력받아 추가한다.
- show_list() : 전체 프롬프트 목록을 출력한다.
- delete_prompt() : 선택한 프롬프트를 삭제한다.
- edit_prompt() : 기존 프롬프트의 정보를 수정한다.
- category_search() : 선택한 카테고리의 프롬프트를 조회한다.
- search_prompt() : 키워드를 이용하여 프롬프트를 검색한다.
- show_detail() : 선택한 프롬프트의 상세 정보를 출력한다.
- toggle_favorite() : 즐겨찾기 상태를 추가하거나 해제한다.
- show_favorites() : 즐겨찾기된 프롬프트만 출력한다.

기능별로 함수를 분리함으로써 코드의 가독성과 유지보수성을 높였다.

# 8. 자료구조 선택 이유

프롬프트 데이터는 Python의 리스트와 딕셔너리를 함께 사용하여 관리하였다.

리스트는 여러 개의 프롬프트를 순서대로 저장하고 반복문을 통해 전체 목록을 출력하거나 검색하기에 적합하다.

딕셔너리는 하나의 프롬프트를 제목, 내용, 카테고리, 즐겨찾기 등의 키와 값으로 관리하기에 적합하다.

예를 들어 하나의 프롬프트는 다음과 같은 구조로 관리된다.

{
    "title": "블로그 글 작성",
    "content": "...",
    "category": "텍스트 생성",
    "favorite": False
}

프로그램에서는 리스트 안에 여러 개의 딕셔너리를 저장한다.

각 필드는 다음과 같이 접근할 수 있다.

prompt["title"]
prompt["content"]
prompt["category"]
prompt["favorite"]

### 리스트와 딕셔너리를 사용하는 이유

장점:

- 리스트를 이용해 여러 프롬프트를 쉽게 관리할 수 있다.
- 반복문을 이용해 전체 데이터를 순회하기 쉽다.
- 딕셔너리를 이용하면 각 필드에 이름으로 접근할 수 있다.
- 새로운 필드를 추가하기 쉽다.

단점:

- 프로그램을 종료하면 데이터가 사라진다.
- 데이터가 많아질 경우 검색 및 관리 효율이 낮아질 수 있다.
- 영속적인 데이터 저장이 필요한 경우 JSON이나 데이터베이스 등의 저장 방식이 더 적합하다.

# 9. 메인 반복문 설계

프로그램은 while 반복문을 이용하여 메뉴를 반복해서 표시한다.

사용자가 하나의 기능을 실행한 후 다시 메인 메뉴로 돌아올 수 있도록 반복 구조를 사용하였다.

사용자가 0번을 선택하면 반복문을 종료하고 프로그램을 종료한다.

기본적인 프로그램 흐름은 다음과 같다.

메뉴 출력
↓
사용자 메뉴 선택
↓
선택한 기능 실행
↓
다시 메뉴 출력
↓
0번 선택
↓
프로그램 종료

while 반복문을 사용하면 프로그램을 종료하기 전까지 여러 기능을 연속해서 사용할 수 있다는 장점이 있다.

# 10. 데이터 영속화 설계

현재 프로그램은 프로그램 실행 중에만 프롬프트 데이터를 유지하며, 프로그램을 종료하면 데이터가 초기화된다.

이는 이번 미션의 기본 요구사항에 맞춘 구조이다.

향후 데이터 영속화 기능을 추가한다면 JSON 파일을 사용하는 방식을 우선적으로 고려할 수 있다.

JSON을 선택하는 이유는 현재 사용하고 있는 리스트와 딕셔너리 구조를 그대로 저장하기 쉽고, Python의 기본 json 모듈을 이용하여 별도의 외부 라이브러리 없이 구현할 수 있기 때문이다.

예상 파일은 prompts.json으로 구성한다.

파일에는 다음과 같은 데이터를 저장할 수 있다.

- title
- content
- category
- favorite

향후 확장한다면 다음과 같은 방식으로 구현할 수 있다.

1. 프로그램 시작 시 prompts.json 파일을 불러온다.
2. JSON 데이터를 Python 리스트와 딕셔너리로 변환한다.
3. 프롬프트 추가, 수정, 삭제 시 데이터를 변경한다.
4. 변경된 데이터를 다시 JSON 파일에 저장한다.
5. 프로그램을 다시 실행해도 이전 데이터가 유지되도록 한다.

# 12. Git 브랜치 전략

기본 브랜치는 main으로 사용하였다.

새로운 기능을 개발하거나 Git 브랜치 작업을 수행할 때는 feature/ 형태의 브랜치를 생성하여 main 브랜치와 분리된 상태에서 작업하였다.

### feature/prompt-list

프롬프트 목록 표시 기능을 개선하기 위해 생성한 브랜치이다.

작업 완료 후 다음과 같은 과정을 수행하였다.

git checkout -b feature/prompt-list

기능을 수정하고 커밋한 후 main 브랜치로 이동하였다.

git checkout main

이후 기능을 main 브랜치에 병합하였다.

### feature/merge-test

브랜치 생성과 병합 과정을 확인하기 위해 별도의 테스트 브랜치를 생성하였다.

git checkout -b feature/merge-test

브랜치에서 README를 수정하고 커밋한 후 main 브랜치에 병합하였다.

이를 통해 main 브랜치와 기능 개발 브랜치를 분리하여 관리하는 Git의 기본적인 브랜치 작업을 경험하였다.

# 13. Git 브랜치 병합

브랜치에서 작업이 완료되면 main 브랜치로 이동한 후 merge 명령을 사용하여 변경사항을 병합하였다.

예시는 다음과 같다.

git checkout main
git merge --no-ff feature/merge-test -m "feature/merge-test 브랜치 병합"

실제 프로젝트에서는 최종적으로 다음과 같은 merge commit이 생성되었다.

3449643 feature/merge-test 브랜치 병합

git log --oneline --graph --all 명령을 사용하면 브랜치가 분리되었다가 다시 병합되는 Git 이력을 그래프 형태로 확인할 수 있다.

# 14. Git 병합 충돌 처리

이번 프로젝트에서 feature/merge-test 브랜치를 main 브랜치에 병합하는 과정에서는 처음 시도에서 이미 변경사항이 포함되어 있어 Already up to date 메시지가 출력되었다.

이를 확인한 후 병합 과정을 명확하게 남기기 위해 기준 커밋으로 되돌린 다음 다시 merge를 수행하였다.

최종적으로 다음과 같은 merge commit이 생성되었다.

3449643 feature/merge-test 브랜치 병합

이번 실제 병합 과정에서는 코드 충돌이 발생하지 않았다.

일반적으로 merge conflict가 발생할 경우 다음 순서로 처리한다.

1. git merge 명령을 실행한다.
2. 충돌이 발생한 파일을 확인한다.
3. 충돌 표시(<<<<<<<, =======, >>>>>>>)가 있는 부분을 확인한다.
4. 유지할 코드를 직접 수정한다.
5. 수정한 파일을 git add한다.
6. merge commit을 완료한다.
7. 프로그램을 실행하여 병합 후 기능이 정상적으로 동작하는지 확인한다.
8. git log --oneline --graph --all로 병합 이력을 확인한다.

즉, 충돌이 발생하면 충돌 원인을 확인하고 코드를 수정한 뒤 다시 커밋하는 과정이 필요하다.
